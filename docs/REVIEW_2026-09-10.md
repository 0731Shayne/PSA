# PSA 系统与界面审查

日期：2026-09-10。对象：当前本地 PSA 工作区。

## 结论

有必要调整界面，但建议保留米白、深绿、课程纸张感的品牌方向，重点重做教师/学生首页的信息结构和高频作答体验。当前更紧迫的问题是判分、学习证据与实验数学表达的正确性；外观调整应建立在这些问题修复之后。

系统已有可运行的题库、任务、答疑、班级诊断、教学包和资料检索结构，业务组织比简单的聊天界面完整。现有测试全部通过，但不能据此认定教学判断和所有交互都可靠。

## 本次验证范围

- 阅读产品定位、上轮审查清单、前后端主要流程与现有测试。
- 后端原有测试：62 项通过。
- 前端数学渲染与关键界面脚本：通过；类型检查及生产构建：通过。
- 真实浏览器查看本地模拟演示的登录、教师首页、班级雷达、教学包、学生任务、逐题作答、学习路径和实验室；手机检查使用 390×844 视口。
- 在临时数据库中独立复现三个后端问题，模拟模型不可用，没有调用真实模型或修改真实班级数据。
- 直接运行实验纯计算函数，核对置信水平；浏览器调节正态分布参数，比较实际 SVG 曲线。
- 本次未验证真实 DeepSeek、MinerU、Ollama/RAGFlow 服务质量、生产 PostgreSQL 部署或并发容量，也未执行完整浏览器自动测试套件。
- 本次只新增这份审查文档，未修改业务代码。

## 一、应优先修复的问题

### 1. P1：降级判分会把数学上不同的答案判为正确【接口复现】

位置：[判分降级逻辑](../backend/src/question_bank/handler.py#L834)。

模型诊断失败时，程序删除空白、反斜杠、花括号和部分标点，然后比较字符串。这会破坏 LaTeX 数学结构。

实际复现：P000020 标准答案为 `19/40`，提交 LaTeX 表示的 `1/940`，系统返回 `correct`。删除花括号后，两者都变为 `frac1940`。

影响：错误作答会进入正确率、掌握度和教师证据，属于教学核心正确性问题。

建议：只实施保留语义的规范化；对明确支持的答案类型做结构化比较，无法可靠判断时进入待复核。增加不同分数、上下标、集合和多选答案的反例验证。

### 2. P1：“独立迁移”可以被看答案后的重复提交污染【接口复现】

位置：[答案开放条件](../backend/src/question_bank/handler.py#L656)、[迁移统计](../backend/src/classroom/analytics.py#L81)。

实际复现流程：创建单题复测任务 → 学生提交“不会做” → 查看该题标准答案 → 原样再次提交 → 班级雷达的独立迁移人数变为 1。

原因：一次作答即可解锁解析；迁移统计只检查任务类型、迁移题标记、正确结果和当次提示数为零，没有排除已看解析、收到前次反馈后重做的情况。

建议：记录答案曝光与辅助事件，明确首次独立作答、订正成功和新的迁移验证之间的区别。订正可以保留为进步证据，验证迁移应换未曝光的新题。同步检查其他入口的解析和提示对证据的影响。

### 3. P1：系统无法判分，会被解释为学生掌握度低【接口及计算复现】

位置：[待复核赋分](../backend/src/question_bank/analytics.py#L64)、[诊断失败降级](../backend/src/question_bank/handler.py#L834)。

`needs_review` 固定按 0.35 参与掌握度，且降级反馈常被归为“表达不完整”。对同一道 P000001 连续两次待复核，复现结果为相关三个知识点均 35 分，并生成三条风险预警。

问题：模型/OCR 不可用、表达暂不能判断，不等于学生能力只有 35%。当前处理把系统不确定性转成了学习负面证据。

建议：待复核保留提交记录和任务交付状态，但暂不进入正确率、掌握度、风险分组的能力判断；另显示待复核数量与原因。只有可靠判断或教师复核后才更新能力证据。

### 4. P1：置信区间实验的连续参数与实际计算不一致【计算复现】

位置：[置信水平控件与 zFor](../web/src/pages/ExperimentLab.tsx#L68)。

控件允许 80%—99% 的每个整数，但临界值只有 80、90、95、99 四档。选择 98% 仍使用 1.96，选择 94% 使用 1.645，选择 89% 使用 1.282。

固定同一随机种子、样本量 30、重复 500 次：95% 与 98% 得到完全相同的 95.0% 实际覆盖率和 0.358 区间半宽；80% 与 89% 同样得到 79.6% 覆盖率。与此同时，参考线却显示用户所选水平。

建议：实现对应置信水平的正态分位数，或把控件明确限制到四个已支持档位；清楚说明本实验的总体分布与已知方差假设。

### 5. P2：正态分布图自动缩放，抵消了希望学生观察的变化【浏览器与计算复现】

位置：[正态分布数据与通用图表](../web/src/pages/ExperimentLab.tsx#L75)。

横轴随 μ±4σ 变化，纵轴随当前峰值变化。实际把 σ 从 1 调至 3，SVG 曲线 242 个坐标的最大差异约为 1.14×10^-13 像素，视觉形状等同不变；坐标数字和说明会变化。

这与“观察标准差增大后曲线变矮、变宽”的探究问题不匹配。改变均值时也会被横轴平移抵消。

建议：提供固定坐标范围、保留上一条曲线或基准曲线，并明确横纵轴名称与刻度。贝叶斯实验也应标出当前先验对应的点，泊松近似应直接叠加二项分布以方便比较。

### 6. P2：切换题目会无提示清空未提交作答【浏览器复现】

位置：[逐题切换时重置输入](../web/src/pages/TaskRunnerPage.tsx#L100)。

手机端第二题输入 `0.023`，进入下一题再返回，输入框恢复为空，字符计数为 0。代码同时清空思路、图片和诊断。教学包有离页保护，学生作答还没有同等保护。

建议：按任务和题号保存草稿；刷新、切题后恢复；未能自动保存时明确提示。已提交作答应可回看，避免学生为了查看结果再次提交。

### 7. P2：实验“重新打开”不能复现当次随机结果【代码确认】

位置：[保存与重新打开实验](../web/src/pages/ExperimentLab.tsx#L45)。

保存了参数、结果摘要和观察，却未保存随机种子；重新打开时还主动增加种子。因此随机实验只能恢复参数，不能恢复当时的结果曲线，旧观察可能与新图不一致。确定性的贝叶斯、正态曲线不受随机种子影响。

建议：保存种子和算法版本，区分“查看历史结果”与“以相同参数重新运行”。

### 8. P2：慢判分和失败状态还不够完整【代码确认，未注入慢网实测】

位置：[作答超时](../web/src/pages/TaskRunnerPage.tsx#L141)、[模型超时及重试](../backend/src/integrations/llm_client.py#L21)、[题目加载失败处理](../web/src/pages/TaskRunnerPage.tsx#L109)。

文字判分前端 30 秒即超时，后端模型默认单次超时 60 秒且可重试；因此前端可能提示失败时后端还在处理并最终保存，用户重试会造成重复记录风险。另在题目详情请求失败时，`question=null` 仍进入骨架屏分支，没有稳定的错误页和重试入口。

建议：统一请求生命周期；重复提交使用幂等标识；明确显示处理中、已保存、待复核和可重试状态。题目请求失败应结束加载态并提供重试。

## 二、外观是否需要调整

### 保留什么

- 米白底、深绿主色、少量暖色提示形成了相对克制的课程气质。
- 页面已有统一导航、卡片、按钮和响应式基础，没必要重新发明所有组件。
- 班级雷达的“下一步为多少人干预”明确连接了数据和行动；学习路径的当前重点也比简单的数据堆砌有效。
- 手机任务卡片基本可用；本次逐题页面测得正文宽度与可用视口宽度相等，未发现整页横向溢出。不能由此推断所有页面都已完成移动验收。

### 应调整什么

| 页面/层面 | 当前问题 | 建议方向 |
|---|---|---|
| 教师首页 | 大标题和示意图占据主要首屏，统计是题库总量、知识点数、题型数；没有今日任务与班级进度 | 首屏显示当前班级、待处理事项、进行中任务、需要复核的作答与干预效果；备课作为明确入口 |
| 学生首页 | 教师与学生共享宣传式大框架；当前任务和下一步建议未直接呈现 | 首屏突出“继续上次任务/作答”，附截止时间、进度、下一项练习及简短推荐依据 |
| 班级雷达 | 总览、发布表单、知识点风险、分组、学生表格、最近任务都在同一长页面 | 保留总览与主要行动，把学生证据、任务和分组分别放入可切换区域；点具体人或知识点再查看依据 |
| 教学包 | 初始状态左边表单较长、右边大面积空白；参数填写先于范例帮助 | 提供可点击的课程示例和最近教学包；高级参数折叠；生成后突出预览、编辑、发布三个工作阶段 |
| 手机作答 | 页头、说明、迟交提示、题号导航占据大量高度，输入和提交容易落到下方；全局底栏持续占位 | 采用紧凑的作答专用布局，优先题干、输入、提交；精简重复说明，避免底栏与公式/输入操作争空间 |
| 学习路径 | 方向正确，但单个建议区在手机上占据较大高度；百分数容易看似过于精确 | 保留当前重点，压缩装饰；显示证据来源、题目数、待复核情况；把置信程度说明为规则估计 |
| 实验室 | 选项和说明占空间，图表语义弱于参数控件；历史参数用 prior/sensitivity 等字段名 | 以图形与当前变化为中心，用中文参数名、固定坐标和对比结果辅助解释 |
| 全局视觉 | 纸色、网格、细边框、小英文标签广泛出现，层级容易趋同 | 纸张风格集中在品牌与内容区域；表单和数据区更清晰干净；统一辅助文字、状态色、间距和边框 |

具体建议：教师主页首屏应回答“哪个班、谁需要处理、接下来做什么”；学生主页应回答“接着做哪道题、多久完成、为什么推荐”。这比扩大标题或增加动画更有价值。

### 内容与视觉的可信度也要一致

- 首页“第 01 章”和侧栏“COURSE · 01”是固定文案，不表示用户进度；若保留为装饰，需要避免让用户误解。
- 首页“热门知识点”取题库统计前八项，数量显示“次”，不是学生访问热度；宜改为“题库知识点分布”和“题”。
- 贝叶斯公式旁放的是一般钟形密度示意，未展示先验与后验更新关系；可以换成与公式对应的频数树或更新示意。
- “没有模型 Key 也能完整生成”等实现说明不宜占据教师工作区，改为教师能理解的生成依据或适用范围。
- “置信度”当前是由题目数、重复次数计算的规则指标，并非经实证校准的统计概率；五题即可达到 100%。产品定位强调可信，应解释口径，避免给出过度确定的印象。

## 三、工程层面后续事项

1. 测试覆盖需要从“存在按钮和关键字符串”扩展到真实行为。`test-critical-ui.mjs` 主要是源码正则检查，无法发现草稿丢失、看解析后被认定迁移、参数与计算不一致。针对上面的反例补测试最有价值。
2. 模型提示词约束不能代替数学判分保障。先保障客观题与受支持表达式，复杂过程题保留待复核能力，并记录判分来源和版本。
3. 掌握度用所有重复作答加权，同题反复练习会增加置信度；建议区分首次作答、辅助作答、订正与新题迁移，避免把熟悉旧题当成广泛掌握。
4. 班级统计和部分学习汇总读取全部作答；当前规模未测出性能瓶颈，但数据增长后应采用数据库聚合、分页或增量统计。本次没有并发测试，不据此声称当前系统已慢。
5. 生产构建成功，但最大 JavaScript 块约 779 kB（gzip 约 256 kB），构建有体积提示。应结合手机实际加载测量决定拆分，不以告警本身认定性能故障。
6. 页面中存在大量压成单行的长逻辑，实验计算、图表与界面混在同一文件；建议伴随修复拆分，便于独立验证数学逻辑。无需为了重构先大改全仓库。

## 四、建议实施顺序与验收

第一步：修复判分降级、待复核证据、答案曝光后的迁移认定、置信区间参数。验收必须覆盖本文可复现反例。

第二步：处理作答草稿、失败重试、超时与重复提交，修复实验坐标和历史可复现性。

第三步：重做教师与学生首页的内容排序，优化手机作答、班级雷达、教学包工作区，再统一视觉细节。

验收关注真实结果：教师能迅速找到待处理事项；学生切题后草稿仍在；待复核不制造学情风险；标准差变化能在同一坐标中被看见；看过解析的订正不会被标为独立迁移。
